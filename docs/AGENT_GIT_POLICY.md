# 仓库内 Git 操作规则

本文件用于约束在当前仓库中执行 Git 操作时的默认流程，避免误把一次性提交、本地直接合并或越权推送当成标准做法。

## 标准顺序

```text
git-start -> git-commit -> git-pr -> review/CI -> git-merge
```

## 各步骤职责

### `git-start`

- 同步最新 `main`
- 创建新的工作分支
- 不负责提交、推送、创建 PR 或合并

### `git-commit`

- 把当前改动整理成一个或多个原子提交
- 如果改动混合了功能、文档、清理或重构，应拆分提交
- 只负责本地提交，不负责推送

### `git-pr`

- 把当前分支推送到远端
- 创建草稿 PR
- 如果分支尚未发布，先执行 `git push -u origin <branch>`

### `review/CI`

- 等待人工审核
- 等待必要检查通过
- 有阻塞问题时不得继续合并

### `git-merge`

- 通过 GitHub PR 合并到 `main`
- 默认使用压缩合并
- 合并后同步本地 `main` 并清理分支

## 默认原则

- 不在 `main` 上直接开发
- 一次提交只处理一个明确关注点
- PR 默认先建草稿
- 不把“本地合并后再推主分支”当成标准路径

## 需要确认的高风险操作

以下操作在执行前必须获得用户明确确认：

- `git push`
- `git merge`
- `git rebase`
- `git reset --hard`
- 删除本地或远端分支
